# QuillDB 左侧对象树全节点优化方案

> 适用版本：1.0.1 现有代码基线
> 分析范围：左侧搜索、区域、连接分组、连接、数据库、Schema、对象分类、数据表、表内分类、字段及其他对象叶子、空白区域和全部右键菜单
> 目标：把当前“可以展开的资源列表”升级为“可靠、可扩展、跨数据库安全的对象导航器”

## 一、结论摘要

当前左侧对象树已经完成基本层级展示和部分核心操作，但各层级的完成度不一致：

- 连接、数据库、数据表三个节点功能相对完整。
- Schema 只有展开/收起，没有右键菜单，也不能刷新、查询或管理。
- 字段、索引、外键、检查约束、触发器、安全策略等表内叶子只能查看名称，不能复制、定位、查看定义或编辑。
- 视图、函数、存储过程等普通对象单击没有行为，主要依赖右键菜单。
- 对象分类和具体对象使用通用 SQL 拼接，缺少数据库引擎能力判断；部分操作名称虽然存在，但生成的 SQL 不适用于当前引擎。
- Schema 下对象没有携带 `schemaName`，查询、查看定义和删除时无法生成可靠的全限定名称。
- 分组虽然区分数据库与 SSH 类型，但前端展示、选择和后端校验没有真正隔离。
- 搜索仅覆盖连接名、引擎和数据库名，不是完整对象树搜索。
- 代码已经预留 `schema`、`connectionGroup`、`section`、`sidebarBlank` 等右键状态，但多数没有触发入口或菜单实现。

因此，不建议继续直接在 `SidebarContextMenu.tsx` 中堆叠条件按钮。应先建立统一节点身份、引擎能力矩阵和菜单命令模型，再逐层补齐功能。

## 二、完整节点结构

当前左侧树实际包含以下层级：

```text
侧栏空白区域
├── 搜索框
├── 数据库连接区域
│   ├── 连接分组
│   │   └── 数据库连接
│   └── 未分组数据库连接
│       └── 数据库
│           ├── Schema（部分引擎）
│           │   ├── 数据表分类
│           │   │   └── 数据表
│           │   │       ├── 字段
│           │   │       ├── 索引
│           │   │       ├── 外键
│           │   │       ├── 检查约束
│           │   │       ├── 触发器
│           │   │       └── 行级安全策略
│           │   └── 视图、函数、过程、序列等对象分类
│           │       └── 具体对象
│           └── 无 Schema 引擎的对象分类与对象
└── SSH 连接区域
    ├── SSH 分组
    └── SSH 连接
```

## 三、逐节点现状审计

| --- | --- | --- | --- |
| 搜索框 | 搜索连接名称、引擎、数据库名称 | 不搜索主机、分组、Schema、表及其他对象；没有过滤器 | P1 |
| 数据库/SSH 区域 | 展开、收起、显示数量 | 没有右键菜单、全部展开/收起、只看已连接等操作 | P1 |
| 连接分组 | 创建、展开、收起、拖入连接、直接删除 | 类型隔离不完整；没有重命名、删除确认、排序、嵌套和右键菜单 | P0 |
| 数据库连接 | 打开/关闭、编辑、新建、复制、删除、移动分组、刷新、环境标签、进程、SQL 文件 | 没有测试、重连、错误详情、复制连接信息、批量操作；刷新语义有限 | P0/P1 |
| SSH 连接 | 打开、创建、关闭终端；编辑、复制、删除 | 终端状态与连接状态反馈不足；缺少快速重连、SFTP 入口和错误详情 | P1 |
| 数据库 | 展开、概览、新建表/数据库、编辑、刷新、查询、字典、SQL 文件、导出和危险操作 | 单击同时承担展开和打开概览；缺少属性、过滤、全部展开；部分能力未按引擎控制 | P0/P1 |
| Schema | 仅展开、收起、显示表数量 | 无选中态、无右键菜单、无刷新、无查询、无创建对象、无属性、无删除 | P0 |
| 数据表分类 | 展开/收起、新建表、导入、导出 | Schema 身份丢失；不能刷新分类、筛选表、批量操作 | P0/P1 |
| 数据表 | 打开数据、展开结构、设计、新建、刷新、复制、SQL、导出、维护、信息、重命名、清空、删除 | 菜单过长；能力依赖引擎但缺少统一矩阵；没有收藏、复制全限定名、依赖分析 | P0/P1 |
| 表内分类 | 展开/收起并显示数量 | 没有右键菜单；不能创建索引/外键/触发器；不能刷新单类元数据 | P1 |
| 字段 | 显示名称、类型和主键图标 | 不是可交互按钮；不能复制、查看属性、生成条件、排序定位或设计字段 | P1 |
| 索引 | 仅显示字符串 | 缺少列、唯一性、类型等结构信息；不能查看定义、重命名、删除 | P1/P2 |
| 外键 | 仅显示字符串 | 缺少引用表/列、更新和删除规则；不能跳转引用对象 | P1/P2 |
| 检查约束 | 仅显示字符串 | 缺少约束表达式与状态；不能查看或管理 | P2 |
| 表触发器 | 仅显示字符串 | 缺少事件、时机、定义、启停状态；不能打开源码 | P1/P2 |
| 安全策略 | 仅显示字符串 | 缺少命令、角色、USING/WITH CHECK 定义；不能管理 | P2 |
| 其他对象分类 | 展开/收起；通用“新建对象” | 不同对象错误共用模板；不支持分类刷新、过滤或引擎能力判断 | P0 |
| 视图/过程/函数等对象 | 右键查询、查看定义、复制名称、部分编辑、删除 | 左键无行为；对象类型映射不完整；SQL 方言和引用规则不可靠 | P0 |
| 侧栏空白区域 | 无功能 | 已预留状态但没有入口；不能新建连接/分组、刷新、全部折叠 | P1 |

## 四、必须先解决的正确性问题

### 4.1 分组类型没有形成完整约束

当前 `ConnectionGroup` 包含 `database/ssh` 分类，但：

- 数据库区域和 SSH 区域渲染时都遍历全部分组。
- “移动到分组”展示全部分组。
- 连接编辑弹窗展示全部分组。
- 后端设置分组时只校验分组存在，不校验连接类型和分组类型匹配。

优化要求：

1. 前端按连接类型过滤可用分组。
2. 后端强制校验类型，不能只依赖前端。
3. 导入连接配置时同时校验分组分类。
4. 删除分组必须确认，并明确连接将移至“未分组”。
5. 增加分组重命名 IPC、服务和持久化方法。

### 4.2 Schema 身份在下级操作中丢失

`SchemaNode` 向数据表和对象菜单传递了连接和数据库，但没有传递 `schemaName`。同名表存在于多个 Schema 时，以下操作可能作用于错误对象：

- 打开数据表
- 查看或生成 DDL
- 重命名、复制或删除表
- 查询、查看定义或删除视图/函数/过程
- 刷新单个对象

优化要求：所有树节点使用统一的对象身份：

```ts
interface DatabaseObjectRef {
  connectionId: number
  databaseName?: string
  schemaName?: string
  objectType?: DatabaseObjectType
  objectName?: string
  parentName?: string
}
```

所有查询、DDL 和元数据接口都通过该身份生成全限定名称，禁止依赖界面标签或字符串截取。

### 4.3 通用对象菜单存在错误回退

当前对象菜单使用少量 `typeMap`，无法识别时回退为 `TABLE`；新建对象时也可能回退为存储过程模板。这会造成：

- 对序列、扩展、自定义类型、域、包、同义词等对象生成错误 SQL。
- 删除未知对象时可能错误执行 `DROP TABLE`。
- PostgreSQL、Oracle、SQL Server 等引擎仍可能使用反引号或 MySQL `SHOW CREATE`。
- 过程、函数、事件等对象被当作可 `SELECT *` 的对象。

优化要求：

- 删除所有“未知类型回退为 TABLE/PROCEDURE”的逻辑。
- 未明确支持的操作不显示，不允许猜测执行。
- DDL 获取、对象删除、对象查询下沉到各数据库适配器。
- 所有危险动作必须由适配器返回明确的受支持能力和 SQL 预览。

### 4.4 表内对象的数据模型过于扁平

`TableItem` 中索引、外键、检查约束、触发器和策略主要以 `string[]` 保存，无法支撑专业对象管理。

建议逐步替换为结构化模型：

```ts
interface IndexNode {
  name: string
  columns: string[]
  unique: boolean
  method?: string
  definition?: string
}

interface ForeignKeyNode {
  name: string
  columns: string[]
  referencedSchema?: string
  referencedTable: string
  referencedColumns: string[]
  onUpdate?: string
  onDelete?: string
}
```

检查约束、触发器和安全策略也应采用对应结构，之后才能可靠实现查看定义、跳转、编辑和删除。

## 五、目标交互设计

### 5.1 搜索与视图工具栏

搜索框升级为“搜索和过滤入口”，支持：

- 模糊搜索连接、主机、分组、数据库、Schema、表和其他对象。
- 搜索结果显示对象路径，例如 `生产库 / app / public / users`。
- 过滤：全部、已连接、未连接、连接异常、生产、测试、开发、数据库引擎。
- 视图选项：隐藏系统数据库、隐藏系统 Schema、分组优先、按名称排序。
- 操作：全部折叠、定位当前编辑器对象、清除筛选。

为避免搜索时加载整台服务器的全部对象，采用两级策略：

1. 优先搜索本地已缓存元数据。
2. 用户明确选择“在服务器中查找”后，再调用数据库元数据搜索接口。

### 5.2 区域节点菜单

数据库连接区域：

- 新建数据库连接
- 新建数据库连接分组
- 全部连接 / 全部断开
- 全部展开 / 全部收起
- 只显示已连接
- 刷新连接列表

SSH 连接区域：

- 新建 SSH 连接
- 新建 SSH 分组
- 关闭全部 SSH 终端
- 全部展开 / 全部收起
- 刷新连接列表

### 5.3 连接分组菜单

- 新建连接
- 新建子分组（第二阶段）
- 重命名分组
- 展开全部 / 收起全部
- 连接全部打开 / 全部关闭
- 导出该分组连接配置
- 删除分组

删除分组只删除分组本身，连接移动到对应区域的“未分组”，并显示确认说明。

### 5.4 数据库连接菜单

建议重新分为五组：

1. 生命周期：打开、关闭、测试、重新连接、错误详情。
2. 工作入口：新建查询、运行 SQL 文件、会话与进程。
3. 管理：编辑、复制配置、移动分组、环境标签、自定义颜色。
4. 信息：刷新元数据、复制主机、复制连接地址、连接属性。
5. 危险操作：删除连接。

状态展示增加：连接中、已连接、未连接、异常、重连中；延迟改为最近一次健康检查结果，而不是仅记录首次打开耗时。

### 5.5 数据库节点菜单

- 打开数据库概览
- 展开/收起对象列表
- 新建查询
- 刷新数据库元数据
- 数据库属性
- 选择要显示的 Schema/对象
- 新建数据库对象（按引擎能力）
- 生成数据字典
- 导入/导出、备份/恢复（按引擎能力）
- 清空全库数据、删除数据库（危险区）

“打开概览”和“展开树”必须分离，单击行为建议只负责打开概览，展开箭头只负责展开树。

### 5.6 Schema 节点菜单

- 打开 Schema 概览
- 新建查询并绑定当前 Schema
- 刷新 Schema
- 新建数据表、视图、函数或过程（按能力显示）
- 复制名称 / 复制全限定名称
- 生成 Schema DDL
- 导出 Schema
- Schema 属性
- 重命名 / 删除 Schema（按引擎能力和权限显示）

Schema 节点必须增加选中态和加载状态，不能继续只作为文件夹使用。

### 5.7 对象分类节点菜单

数据表、视图、函数等分类节点统一具备：

- 新建对应对象
- 刷新该分类
- 搜索/过滤该分类
- 展开全部 / 收起全部
- 复制对象名称列表
- 批量导出（适用时）

分类菜单由能力矩阵生成，不再使用一个通用 `CREATE PROCEDURE` 模板覆盖未知对象。

### 5.8 数据表节点菜单

数据表菜单建议压缩为：

- 打开数据
- 打开结构设计
- 新建查询
- 刷新
- 复制名称 / 复制全限定名称
- 生成 SQL：SELECT、INSERT、UPDATE、DELETE、DDL
- 复制/迁移数据表
- 导入/导出
- 依赖关系 / ER 图
- 表信息
- 重命名
- 引擎工具
- 清空和删除（危险区）

“引擎工具”只显示适用于当前数据库的动作。例如 MySQL 使用 CHECK/OPTIMIZE/ANALYZE，PostgreSQL 使用 VACUUM/ANALYZE，禁止显示不可执行的跨引擎命令。

### 5.9 表内分类与叶子节点菜单

字段分类：

- 新建字段
- 刷新字段
- 展开全部 / 收起全部
- 复制字段列表

字段节点：

- 查看字段属性
- 在表设计器中定位
- 复制字段名 / 带引号字段名 / 全限定字段名
- 添加到 SELECT
- 添加到 WHERE / ORDER BY / GROUP BY
- 查看引用和依赖
- 重命名 / 删除字段（危险动作）

索引节点：

- 查看定义
- 复制 DDL
- 在表设计器中定位
- 重建/分析（按引擎支持）
- 重命名 / 删除

外键节点：

- 查看关系
- 跳转到引用表
- 复制 DDL
- 在 ER 图中定位
- 编辑 / 删除

检查约束、触发器和策略节点：

- 查看定义
- 复制名称 / DDL
- 打开源码或设计器
- 启用/禁用（支持时）
- 重命名 / 删除

### 5.10 视图、函数、过程等对象节点

所有具体对象应具备一致的基础动作：

- 左键打开对象详情或源码。
- 双击在独立标签页打开。
- 复制名称和全限定名称。
- 查看由适配器返回的真实 DDL。
- 刷新该对象。
- 查看依赖和被依赖对象。

对象特有动作：

- 视图/物化视图：查询数据、编辑定义、刷新物化视图。
- 函数/过程：打开源码、生成调用模板、可视化编辑。
- 序列：查看当前值、获取下一个值、重置。
- 触发器/事件：查看定义、启用、禁用。
- 扩展：查看版本和依赖；升级或删除需要高风险确认。
- 同义词/外部表：打开目标对象、查看映射关系。
- Elasticsearch 索引/映射/别名/数据流：使用 Elasticsearch 专用动作，不生成 SQL。
- Redis 键：使用键类型、TTL、值查看和删除等专用菜单，不复用关系型表菜单。

### 5.11 侧栏空白区域菜单

- 新建连接
- 新建分组
- 导入连接配置
- 刷新连接列表
- 全部折叠
- 视图设置

## 六、技术架构方案

### 6.1 统一节点模型

把散落的 `kind + connection + database + groupKey + objectName` 收敛为判别联合：

```ts
type SidebarNode =
  | SectionNode
  | ConnectionGroupNode
  | ConnectionNode
  | DatabaseNodeRef
  | SchemaNodeRef
  | ObjectGroupNode
  | TableNodeRef
  | TableObjectGroupNode
  | ColumnNodeRef
  | IndexNodeRef
  | ForeignKeyNodeRef
  | RoutineNodeRef
  | GenericObjectNode
  | SidebarBlankNode
```

每个节点必须有稳定 `nodeId`、完整父路径和 `DatabaseObjectRef`，菜单、刷新、选中和缓存都以节点身份操作。

### 6.2 引擎能力矩阵

增加统一能力定义：

```ts
interface EngineCapabilities {
  schemas: boolean
  objectTypes: DatabaseObjectType[]
  actions: Partial<Record<DatabaseObjectType, ObjectAction[]>>
  maintenance: TableMaintenanceAction[]
  supportsRenameDatabase: boolean
  supportsDropDatabase: boolean
  supportsProcessList: boolean
}
```

菜单只根据能力矩阵渲染。具体 SQL、标识符引用、全限定名称、DDL 获取和删除动作由 adapter 实现，React 组件不得直接拼接数据库方言 SQL。

### 6.3 菜单命令注册表

将单个超长的 `SidebarContextMenu.tsx` 拆分为：

```text
sidebar-menu/
├── SidebarContextMenu.tsx
├── command-registry.ts
├── connection-commands.ts
├── database-commands.ts
├── schema-commands.ts
├── table-commands.ts
├── table-object-commands.ts
└── generic-object-commands.ts
```

每个命令声明：适用节点、是否可见、是否禁用、危险等级、执行函数和快捷键。这样才能可靠控制不同引擎的菜单差异。

### 6.4 状态拆分

侧栏状态建议拆为：

- `treeExpansionState`：展开状态。
- `treeSelectionState`：单选、多选、键盘焦点。
- `treeLoadingState`：节点级加载和错误。
- `treeFilterState`：搜索与过滤。
- `treeMetadataCache`：对象元数据和更新时间。
- `contextMenuState`：当前节点和菜单位置。

展开状态、过滤条件和侧栏宽度持久化；连接中的临时状态不持久化。

### 6.5 元数据加载与缓存

- 连接打开时只加载数据库/Schema名称，不一次性加载所有字段。
- 展开分类时加载对象名称。
- 展开表结构时再加载字段、索引和约束。
- 每个节点记录 `idle/loading/loaded/error/stale`。
- 支持刷新当前节点、递归刷新和强制完整刷新。
- 大量对象使用分批加载或虚拟列表，避免一次渲染几千个 DOM 节点。
- 缓存键包含连接、数据库、Schema、对象类型和对象名。

### 6.6 后端与 IPC 改造

第一批新增接口：

```text
connections:testSaved
connections:reconnect
connections:renameGroup
connections:getHealth
metadata:listChildren
metadata:refreshNode
metadata:getObjectDefinition
metadata:searchObjects
objects:executeAction
```

所有 IPC 输入继续通过 `ipc-validators` 校验。危险对象操作返回 SQL 预览或操作摘要，前端确认后才能提交执行。

## 七、分阶段实施计划

### 阶段 0：正确性和风险收口（P0，3～5 人日）

- 修复数据库/SSH分组隔离和后端约束。
- 为 Schema 下节点补齐 `schemaName`。
- 删除未知对象类型的 TABLE/PROCEDURE 回退。
- 隐藏当前引擎不支持的菜单项。
- 修复对象引用符、全限定名称和 DDL 获取职责。
- 将数据库展开与打开概览的交互分离。

验收标准：

- 数据库连接不能进入 SSH 分组，反之亦然。
- 同一数据库不同 Schema 中的同名表可以被准确操作。
- 未支持对象不会生成或执行猜测 SQL。
- PostgreSQL、MySQL、SQLite 的基础菜单只显示可执行操作。

### 阶段 1：补齐所有节点基础能力（P0/P1，5～8 人日）

- 完成区域、分组、Schema、表内分类、叶子和空白区域菜单。
- 增加分组重命名和删除确认。
- 增加对象左键默认行为、选中态和加载态。
- 增加复制名称、复制全限定名称、刷新、属性等通用操作。
- 拆分菜单命令注册表。

验收标准：

- 所有可见节点均有明确的左键、双击和右键行为。
- 任意菜单动作都能根据节点路径准确定位对象。
- 危险操作全部位于底部危险区并要求确认。

### 阶段 2：搜索、过滤和批量导航（P1，5～7 人日）

- 扩展搜索范围并显示对象路径。
- 增加已连接、环境、引擎和系统对象过滤。
- 增加全部折叠、定位当前编辑器对象。
- 增加多选和批量连接、移动、刷新、导出。
- 保存用户过滤和展开偏好。

验收标准：

- 可以在连接较多时快速找到主机、数据库、Schema和表。
- 当前编辑器对象能被自动定位并高亮。
- 批量操作对失败项给出逐项结果，不出现整体假成功。

### 阶段 3：专业对象管理（P1/P2，8～12 人日）

- 结构化索引、外键、约束、触发器和策略数据模型。
- 实现查看定义、跳转依赖、复制 DDL和设计器定位。
- 完善视图、函数、过程、序列等对象专属动作。
- 为 Redis、MongoDB、Elasticsearch提供专用对象菜单。
- 增加依赖关系和 ER 图入口。

验收标准：

- 所有对象定义来自适配器真实元数据，不用字符串猜测。
- NoSQL 节点不出现关系型 SQL 操作。
- 删除、重命名和编辑动作都有能力检查和准确错误提示。

### 阶段 4：性能与连接体验（P2，5～8 人日）

- 节点级懒加载、缓存和过期状态。
- 大对象列表虚拟滚动或分批加载。
- 连接健康检查、重连、错误详情和最近延迟。
- 可配置自动重连、Keep Alive、超时和元数据刷新间隔。
- 收藏、置顶、最近使用节点。

验收标准：

- 大型服务器展开连接时不一次加载全部字段。
- 5000 个对象的分类可以平滑搜索和滚动。
- 网络中断后状态及时变化，用户可以手动或自动重连。

## 九、建议的首个交付版本

首个版本不追求一次做完全部专业对象管理，建议包含：

1. 分组类型隔离、重命名和删除确认。
2. Schema 完整身份、选中态和右键菜单。
3. 统一引擎能力矩阵，移除危险 SQL 回退。
4. 区域、空白区、对象分类的基础菜单。
5. 字段节点的查看、复制和查询构造操作。
6. 全限定名称复制与当前节点刷新。
7. 搜索扩展到主机、分组、数据库、Schema和表。
8. 测试连接、重新连接和错误详情。

这个版本可以先解决正确性、可发现性和日常效率三个核心问题，同时为后续索引、外键、触发器和 NoSQL 专用功能留下稳定扩展点。
